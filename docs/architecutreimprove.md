## Top findings (executive)

1. **Control plane is real:** `apps/api` + `apps/dashboard` + `infra/worker-service` provision **Finance tenants only** (Docker tenant stack = Stockix Finance server/webapp/MySQL/Mongo/Redis).
2. **POS has a parallel control plane:** `services/posnew/apps/saas-dash` talks to **POS backend** `/api/platform/v1` (MongoDB org/license model) — **not** `apps/api`. This is the dashboard to retire after migration.
3. **PMS is not merged:** `services/pmsfull` holds **two separate products** — `pesan-pms` (hotel PMS, SQLite + better-auth) and `RentTools.io` (STR iCal sync, Prisma/Postgres). **No Stockix integration** found.
4. **Chatwoot is vendored only:** `services/chatlive` is full Chatwoot Rails source; **zero** references in `apps/api`, worker, or tenant stack.
5. **Production-ready for Finance-first tenants:** YES for Finance path; **NO** for multi-product (POS/PMS/Chat) platform.

## Recommended build order (short)

1. **Decide product boundary** — Stockix dashboard owns all products vs Finance-only + product-specific consoles.
2. **POS integration contract** — Stockix API proxies or subscribes to POS `platformV1` for org/device/metrics, or POS orgs become first-class in `packages/db`.
3. **Docker images** — POS frontend/saas-dash/PMS images for tenant stack (Finance already has images).
4. **PMS** — pick merge strategy (pesan-pms vs RentTools) before any provisioning work.
5. **Chatwoot** — image + provisioning job + white-label env (currently absent).
